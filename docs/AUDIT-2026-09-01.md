### P0-2. Xung đột từ vựng làm sụp toàn bộ Opportunity Index
**File**: `quality_evaluator.py:36` & `:46` · `strategic_reasoner.py:73` & `:41`

```python
FOREIGN_STOPWORDS = { ..., "dan", "dari", ...,  "tutorial", ... }   # Indonesian + PT
VI_CORE_WORDS     = { ..., "huong", "dan", "cach", "lam", ... }     # Vietnamese
TECH_LOAN_WORDS   = { ..., "tutorial", "guide", "free" }
```

**Root cause**: `is_vietnamese()` chạy **Layer 1 (reject stopword ngoại) TRƯỚC Layer 3 (accept từ lõi Việt)**. Hai tập hợp giao nhau ở 2 token — và cả 2 đều là token tần suất cực cao trong tiếng Việt:
- `"dan"` — trùng với "dan" tiếng Indonesia
- `"tutorial"` — vừa là `FOREIGN_STOPWORDS` (PT) vừa là `TECH_LOAN_WORDS`

Kiểm chứng thực thi:
```
is_vietnamese('Huong dan cai dat n8n')                      -> False   ❌
is_vietnamese('huong dan tu dong hoa cho doanh nghiep')      -> False   ❌
is_vietnamese('Tutorial AI agent cho nguoi Viet')            -> False   ❌
is_vietnamese('Cach lam chatbot ai')                         -> True    ✓
```

**Tác động lan truyền (đây là lý do nó là P0, không phải P1)**:
1. `_discover_market_opportunities` → `vn_videos = [v for v in matching_videos if self._is_vietnamese(...)]` → **`vn_count = 0`**
2. → `supply_score = 0.0`
3. → nhánh `vn_count == 0` → `opp_type = "UNVERIFIED_DEMAND_GAP"`, `OI = demand × 0.25`
4. → **mọi keyword đều bị gán nhãn "chưa có bằng chứng nguồn cung" dù thực tế có hàng chục video Việt**

Reproduce end-to-end: đưa 5 video YouTube `"Huong dan ai agent cho doanh nghiep {i}"` + demand 70 → output `supply=0.0, type=UNVERIFIED_DEMAND_GAP, OI=17.5`. Đây chính là số liệu đang nằm trong 3 file case study reference đã commit ở `reports/`.

Phụ đề: `language_precision` cũng bị kéo xuống bởi cùng nguyên nhân → `overall_confidence` (25% trọng số) sai theo.

**Fix**:
1. Đảo thứ tự: chạy Layer 2/3 (bằng chứng *dương* về tiếng Việt) trước, chỉ dùng stopword ngoại để phá vỡ thế hòa.
2. Assert bất biến trong test: `FOREIGN_STOPWORDS.isdisjoint(VI_CORE_WORDS | TECH_LOAN_WORDS)` — chặn regression khi seed lexicon mới từ DB.
3. Chấm điểm theo **tỷ lệ** thay vì reject nhị phân: `score = |vi_evidence| - |foreign_evidence|`.

### P0-5. `ConnectorQuotaExceededException` bị nuốt → circuit breaker quota là dead code
**File**: `youtube_plugin.py:297` (raise) vs `:372` (swallow)

```python
        for raw_kw in keywords:
            try:
                async with httpx.AsyncClient(timeout=15.0) as client:
                    ...
                    if "quotaExceeded" in reasons or resp.status_code == 429:
                        raise ConnectorQuotaExceededException(...)   # dòng 297
                    ...
                _YOUTUBE_QUERY_CACHE[cache_key] = kw_signals         # dòng 371
            except Exception as e:                                   # dòng 372
                logger.warning(f"YouTube search error for keyword '{raw_kw}': {e}")
```

**Root cause**: exception được raise **bên trong** phạm vi của `except Exception` cùng hàm.

**Tác động chuỗi 3 tầng — trả lời trực tiếp câu hỏi 3 của bạn về circuit breaker khi gặp 429/403**:
1. Exception không bao giờ thoát khỏi `search_signals` → `registry._safe_search` gọi **`breaker.record_success()`** → circuit breaker **không bao giờ mở** cho YouTube dù quota đã cạn 100%.
2. `execute_mission.py:48` có comment *"Fail-safe: Nếu một nguồn gặp Quota Exceeded (ví dụ YouTube 429), bảo toàn dữ liệu cũ"* — cơ chế này dựa trên tín hiệu không bao giờ tới. Nó *tình cờ* vẫn hoạt động (vì so sánh platform rỗng), nhưng không phải theo cách code nghĩ.
3. **Cache bị đầu độc**: `_YOUTUBE_QUERY_CACHE[cache_key] = kw_signals` nằm *trong* `try`. Nếu 403 vì API key sai (không phải quota), cả 2 nhánh `if/elif` đều không khớp → `video_ids` rỗng → **cache một list rỗng với TTL 86.400s**. Một lỗi 403 thoáng qua làm mù YouTube connector **trọn 24 giờ**.

**Fix**:
```python
            except ConnectorQuotaExceededException:
                raise                      # để breaker thấy
            except Exception as e:
                logger.warning(...)
                continue                   # KHÔNG cache kết quả rỗng
```
Chỉ cache khi `kw_signals` non-empty (hoặc dùng TTL ngắn riêng cho negative cache, ~300s).

### P0-6. Khóa mã hóa mặc định là hằng số công khai suy ra được từ repo
**File**: `infrastructure/auth/crypto.py:15-23`

```python
    if not raw_key:
        derived = hashlib.sha256((settings.DATABASE_URL or "fn-ignis-default-salt").encode()).digest()
        raw_key = base64.urlsafe_b64encode(derived).decode()
```

**Root cause**: khi `IGNIS_ENCRYPTION_KEY` rỗng (mặc định trong `config.py:25`), khóa = `sha256(DATABASE_URL)`. Mà `DATABASE_URL` cũng có default hardcoded trong `config.py:14`: `postgresql://postgres:postgres@localhost:5432/ignis`.

**Tác động**: Với **mọi** cài đặt mặc định của một dự án open-source, khóa "AES-256" là một hằng số mà bất kỳ ai đọc `config.py` cũng tính ra được trong 1 dòng Python. Session cookie TikTok trong DB **coi như plaintext**. Không có một dòng warning nào. Thêm nữa: đổi `DATABASE_URL` (dời host, đổi password) → **toàn bộ credentials đã lưu không giải mã được nữa**, hard fail.

Vấn đề phụ cùng file:
- Passphrase do user cung cấp bị `sha256` **không salt, không KDF** (dòng 22) → brute-force nhanh với passphrase entropy thấp. Cần `scrypt`/`PBKDF2` + salt lưu kèm ciphertext.
- Nhãn `"algorithm": "AES-256-Fernet"` và log `"đã mã hóa AES-256"` **sai về mặt kỹ thuật**: Fernet là **AES-128-CBC + HMAC-SHA256**. Với dự án security-sensitive sắp public, một tuyên bố crypto sai là vấn đề uy tín, không chỉ là typo.
- `decrypt_credentials` trả plaintext khi thiếu cờ `_encrypted` (dòng 58-60) → cho phép silent downgrade nếu ai đó ghi được vào DB.

**Fix**: **fail-fast**. Nếu `IGNIS_ENCRYPTION_KEY` rỗng → raise và in hướng dẫn `python -c "from ignis.infrastructure.auth.crypto import generate_new_key; print(generate_new_key())"`. Không bao giờ tự suy khóa từ connection string. Sửa nhãn thành `"Fernet-AES128-CBC-HMAC-SHA256"`.

### Nhóm A — Nhiễm chéo dữ liệu & tính bất biến

**P1-1. TTLCache trả về object mutable dùng chung → nhiễm chéo giữa các mission**
`youtube_plugin.py:22` (cache global) + `execute_mission.py:60-61` + `semantic_clusterer.py:82-83`
```python

...
```

Cache lưu **chính các instance `TrendSignal`**, không phải copy. Mission A chạy → cache. Mission B cùng keyword trong 24h → cache hit → **trả về đúng những object đó** → bị ghi đè `mission_id`/`cluster_id` của B. Object trong cache giờ mang state của mission gần nhất. **P1-2. Lexicon tích lũy vĩnh viễn trên singleton → Quality Gate nhiễm chéo**
`refinement_orchestrator.py:52-60` + `autonomous_discovery.py:196-206`
`_evaluator`/`_reasoner` là singleton process-wide (`_init_components()`). Mỗi mission gọi `get_domain_lexicons()` **không truyền domain** → nạp **toàn bộ** mọi domain (VN fashion + global SaaS + PT stopwords) vào `_custom_lexicon`, **không bao giờ xóa**. Mission "US SaaS" chạy sau mission "fashion VN" thừa hưởng toàn bộ từ vựng fashion tiếng Việt. Domain-scoping trở nên vô nghĩa, và bộ nhớ tăng đơn điệu. Fix: tạo evaluator/reasoner **per-mission** (chúng stateless ngoài lexicon), lọc theo domain liên quan.

**P1-3. Từ vựng đa từ không bao giờ khớp → `register_domain_lexicon` gần như vô hiệu**

```

register_terms(['ao','linen','local','brand']) → is_vietnamese('Ao linen local brand') = True
```
Nghĩa là **phần lớn ~200 dòng seed trong `sql/003` và `sql/004`** ("huong dan", "cach lam", "tiktok shop", "quiet luxury", "mcp server"...) không tác động gì tới Quality Gate. Tool MCP `register_domain_lexicon` — bước 1 của SOP — về cơ bản là no-op. Fix: khớp n-gram (`term in text_lower` cho term có khoảng trắng) hoặc tách term thành unigram khi nạp.

**P1-4. Không idempotent: harness & discovery không xóa signal cũ → nhân bản dữ liệu**
`refinement_orchestrator.py:111` · `autonomous_discovery.py:152` · so với `execute_mission.py:67`
`ExecuteMissionUseCase` gọi `delete_mission_signals()` trước khi save (replace mode). `run_mission_harness()` và `AutonomousDiscoveryUseCase.execute()` **thì không**. Chạy lại harness trên cùng mission → signal nhân đôi trong DB (SQLite PK là `uuid4()` mới mỗi lần → duplicate chắc chắn; Postgres `BIGSERIAL` cũng vậy) → `get_mission_signals()` trả 2× → `total_estimated_reach`, `supply_score`, `view skew ratio` đều bị thổi phồng. Cộng hưởng nguy hiểm với **P1-13** (mỗi lần worker restart lại chạy discovery ngay).

**P1-5. "Atomic Replace mode" không hề atomic**
`execute_mission.py:66-73` — `delete_mission_signals()` commit, *rồi* `save_signals()`. Nếu save fail (mất kết nối, constraint) → **mất toàn bộ dữ liệu mission, không rollback**. Comment ghi "Atomic Replace mode" là sai. Fix: một transaction duy nhất; port cần method `replace_mission_signals(mission_id, signals)` để adapter tự lo tính nguyên tử.

**P1-6. Shortcode trùng → SQLite XÓA MẤT mission cũ**
`sqlite_repository.py` schema `shortcode TEXT UNIQUE` + `INSERT OR REPLACE`. `INSERT OR REPLACE` xóa row xung đột trên **bất kỳ** unique constraint — kể cả `shortcode`, không chỉ PK. Reproduce:
```
save_mission(Alpha, shortcode='VN-DUP-7D-0001')
save_mission(Beta,  shortcode='VN-DUP-7D-0001')   # id khác
→ list_missions() = 1 mission: ['Mission Beta']    # Alpha đã bị xóa vĩnh viễn
```
Signals của Alpha thành orphan (schema không có FK). Với suffix chỉ **4 hex** (`entities.py:15`, 65k không gian) và tiêu đề tiếng Việt bị co về cùng slug (xem P1-7), xác suất trùng là thực tế. Fix: dùng `INSERT ... ON CONFLICT(id) DO UPDATE` (như code đã làm đúng cho `platform_credentials`), nâng suffix lên 8 hex, và raise lỗi rõ ràng khi shortcode trùng.

**P1-7. Shortcode tiếng Việt sinh ra vô nghĩa**
`entities.py:12` — `re.findall(r"[a-zA-Z0-9]+", title.upper())` cắt tại dấu tiếng Việt:
```
'Xu hướng AI Agent tại Việt Nam' → VN-XU-H-7D-01     ❌
'AI Agent Trends Vietnam'        → VN-AI-AGENT-7D-01  ✓
```
Bằng chứng đã hiện hữu: `reports/` chứa **hơn 30 file** `mission_vn-xu-h-7d-*.html`. Fix: normalize NFD → strip combining marks → slug (`unicodedata`), để "Xu hướng AI" → `XU-HUONG-AI`.

### Nhóm B — Thống kê & tính trung thực số liệu

**P1-9. Cơ hội "chưa kiểm chứng" xếp trên cơ hội đã kiểm chứng**

**P1-10. Damping áp lên OI âm làm nhãn thị trường lật ngược theo cỡ mẫu**

**P1-11. `language_precision` sai mẫu số (câu hỏi 2 của bạn)**

**P1-12. `language_precision = 100%` cứng cho mọi geo ≠ VN**

**P1-13. `data_freshness_score` (30% trọng số — cao nhất) gần như là hằng số**

**P1-14. `evaluate_quality()` không nhận timeframe của mission**

**P1-15. Luật View Skew bắn nhầm khi n=1**

**P1-16. Trộn đơn vị: views và likes vào cùng một field**

**P1-17. Ngưỡng BREAKOUT không thể đạt được với cluster đơn nền tảng**

### Nhóm C — Resilience của scraper (câu hỏi 3)

**P1-19. Soft-block không sinh exception → circuit breaker mù**
Không có chỗ nào trong `tiktok_plugin.py`, `threads_plugin.py`, `reels_plugin.py` kiểm tra 429/403 (chỉ YouTube có — xem P0-5). Khi TikTok trả captcha-wall/empty grid: `page.goto` thành công, 0 card, `return []` → `_safe_fetch` gọi **`record_success()`** → breaker vĩnh viễn CLOSED. Registry ghi audit `INGRESS_SUCCESS · 0 signals`. **Đây là lỗ hổng resilience quan trọng nhất**: chế độ hỏng phổ biến nhất của scraper (bị block im lặng) là chế độ duy nhất mà circuit breaker không thể thấy. Fix: coi "0 signal khi lẽ ra phải có" là failure — kiểm tra marker của captcha/verify page, kiểm tra HTTP status của navigation response, và cho `_safe_fetch` treat empty-result-streak như một failure signal.

**P1-20. Fallback Matrix chỉ tồn tại cho suggestions, không cho ingress chính**
`tiktok_plugin.py:449-453`. Ma trận 4 tầng (sniff → in-page JS → DOM pills → HTTP) chỉ có trong `fetch_suggestions()`. `_fetch_via_playwright()` — đường dẫn cào video chính — có **tầng 1 (sniff) + tầng 3 (DOM)**, không có in-page JS fetch, **không có HTTP fallback**. Khi Playwright chưa cài: `except ImportError: return []` (chỉ 1 dòng warning). Vậy trong cài đặt "zero-Playwright" mà tài liệu quảng bá, TikTok video signals **luôn rỗng** trong khi suggestions vẫn chạy. Fix: hoặc bổ sung HTTP fallback thật cho ingress, hoặc **sửa README** để không hứa điều code không làm.

**P1-21. Closure capture làm nhiễm chéo suggestions giữa các keyword**
`tiktok_plugin.py:164-183`
```python
                for kw in keywords[:10]:
                    guide_words: List[str] = []          # rebind mỗi vòng
                    async def handle_suggest(resp): ...   # closure trên TÊN guide_words
                    page.on("response", handle_suggest)   # đăng ký TRÊN CÙNG page, không remove
```
Python closure bắt **biến**, không bắt **giá trị**. Sau vòng thứ 2, cả N handler đã đăng ký đều trỏ tới `guide_words` **mới nhất** → response chậm từ keyword 1 append vào list của keyword N. Đồng thời handler tích lũy (10 keyword → 10 listener, mỗi response bị parse 10 lần). Đây cũng là nguồn của `RuntimeWarning: coroutine ... never awaited` trong test suite. Fix: `functools.partial(handle, sink=guide_words)`, và `page.remove_listener()` cuối mỗi vòng (hoặc `page` mới mỗi keyword).

**P1-22. Fallback đổi nguồn dữ liệu nhưng không đổi nhãn**
`tiktok_plugin.py:258-317`. `_fetch_suggestions_http_fallback` truy vấn **Google Suggest API**, nhưng: (a) tool MCP mô tả *"autocomplete queries from TikTok"*, (b) payload trả về vẫn ghi `"platform": "tiktok"`, (c) **không có field nào cho biết đây là fallback**. Agent không thể phân biệt dữ liệu TikTok thật với suy luận từ Google. Với sản phẩm market-intelligence, đây là vấn đề provenance. Ngoài ra Probe 2 hardcode tiếng Việt `f"cách làm {kw}"` cho **mọi** geo → mission US truy vấn tiếng Việt. Fix: thêm `"source": "google_suggest_fallback"` + `"degraded": True`; localize probe theo geo.

**P1-23. `is_healthy()` trả `True` cứng cho 4/6 connector**
`tiktok_plugin.py:51` · `creative_center_plugin.py:41` · `threads_plugin.py:30` · `reels_plugin.py:30`. Chỉ YouTube và Google Trends probe thật. Health probe cycle 6h (commit `40ae617`) ghi audit `HEALTHY` cho đúng 4 connector scraper mong manh nhất — tức là tính năng có tác dụng ngược: tạo cảm giác an toàn giả. **P1-24. Breaker state chỉ trong RAM, mỗi process một bản**
`registry.py:52`. MCP server và scheduler daemon mỗi bên có `ConnectorPluginRegistry` riêng → breaker riêng. **P1-25. Playwright: rò rỉ tài nguyên và không có watchdog**
`tiktok_plugin.py:471`, `:249`, `:391` — `browser = await p.chromium.launch(...)` với `await browser.close()` **chỉ trên happy path**, không `try/finally`. `context` không bao giờ close tường minh. ### Nhóm D — Scheduler & lifecycle (câu hỏi 5)

**P1-26. Env var của scheduler không tồn tại → knob trong docker-compose là vô nghĩa**

**P1-27. Mỗi lần restart lại chạy Discovery + Health Probe ngay lập tức**

**P1-28. Graceful shutdown không cancel công việc đang chạy**
`scheduler.py:140-165`. `stop()` chỉ set event; loop chỉ kiểm tra **giữa** các cycle. SIGTERM đến giữa `run_ingress_cycle` (scrape Playwright, có thể vài phút) → cycle không bị cancel → Docker SIGKILL sau 10s → **kill giữa lúc ghi DB**. Ngoài ra `loop.add_signal_handler(SIGINT, scheduler.stop)` thay thế handler mặc định → `KeyboardInterrupt` không còn được raise, nên Ctrl+C lần hai **không** force-exit; nếu cycle treo, user không thể dừng. Fix: chạy cycle như `asyncio.Task`, cancel task khi shutdown, và sau lần stop() thứ hai thì `signal.default_int_handler`.

**P1-29. `cachetools` không khai báo dependency; `google-api-python-client` không dùng**
