# Data Model: Decision-Grade Evidence Qualification

## Existing records used unchanged

- `research_missions`: identifies the Attention or Market mission and its workspace/surface.
- `market_brief_revisions`: immutable Market frame; a Market mission already points to exactly one.
- `sources`: canonical external-object identity used to count independent evidence.
- `observations`: immutable sightings; qualification never mutates or deletes them.
- `mission_evidence`: canonical `(mission_id, observation_id)` association.
- `mission_run_journals`: stable run identity and completion state.

## MissionProbeOutcome

One factual result for one connector surface during one workspace mission run.

| Field | Meaning | Rules |
|---|---|---|
| `id` | Stable record identity | UUID; generated by the database |
| `run_id` | Run that executed the probe | Required; references `mission_run_journals`; cascade on run deletion |
| `platform` | Logical platform | Required canonical platform value |
| `connector_surface` | Exact probe surface | Required; unique within a run |
| `status` | Observed run outcome | `HEALTHY`, `EMPTY_NO_DATA`, `AUTH_REQUIRED`, `RATE_LIMITED`, or `DEGRADED` |
| `signals_collected` | Number returned by this surface before mission-level preservation | Integer greater than or equal to zero |
| `query_fingerprint` | Digest of keyword/geo/timeframe/scope sent to the surface | Required; never contains credentials |
| `completed_at` | When this surface finished or failed | Required UTC instant |

**Uniqueness**: `(run_id, connector_surface)`.

The mission is derived through the referenced run journal. Storing a second mission foreign key
would permit a probe outcome to name a mission different from the run that produced it.

**Interpretation**:

- `EMPTY_NO_DATA` is a measured zero only for the query identified by `query_fingerprint`.
- Failure, missing auth, rate limiting, and circuit-open behavior map to non-zero-evidence statuses;
  they never count as zero supply.
- A reopened mission uses outcomes from its latest completed run. A failed later run does not
  rewrite the evidence meaning of the last completed run.

## MissionEvidenceQualification

One persisted semantic judgment for one observation in one mission frame.

| Field | Meaning | Rules |
|---|---|---|
| `id` | Stable record identity | UUID; generated by the database |
| `mission_id` | Mission whose question is being answered | Part of the foreign key to `mission_evidence` |
| `observation_id` | Observation being judged | Part of the foreign key to `mission_evidence` |
| `brief_revision_id` | Exact Market Brief frame | Required for Market; absent for Attention; references `market_brief_revisions` |
| `frame_fingerprint` | Digest of the immutable judgment frame | Required; submission must match the server-provided value |
| `relation` | How the observation relates to the frame | `QUALIFIED_SUPPORT`, `CONTEXT_ONLY`, `EXCLUDED_IRRELEVANT`, `UNASSESSED` |
| `purpose` | What a qualified observation can measure | `DEMAND`, `SUPPLY`, `VOC`, `CONTEXT` |
| `confidence` | Evaluator uncertainty | Decimal from `0.0` through `1.0`; absent only for unassessed failures |
| `reason_code` | Bounded explanation | Required enum; no free-form prompt transcript |
| `judged_by` | Agent/runtime identifier | Required bounded string; contains no credential |
| `model` | Optional evaluator model identifier | Bounded string; metadata only |
| `created_at` | Persisted judgment time | Required UTC instant |

**Uniqueness**: `(mission_id, observation_id)`.

**Foreign key**: `(mission_id, observation_id)` references the same unique pair on
`mission_evidence` with cascade deletion. A mission cannot qualify an observation it does not hold.

**Brief rules**:

- Market: `brief_revision_id` must equal the mission's persisted Brief revision.
- Attention: `brief_revision_id` must be absent.
- Missions without a surface do not create qualification rows.

**Reason codes**:

- `DIRECT_TO_FRAME`: directly addresses the declared scope or Market Brief.
- `ADJACENT_ONLY`: related topic, but does not support this question.
- `KEYWORD_ONLY`: repeats probe text without addressing the question.
- `WRONG_AUDIENCE_OR_PROBLEM`: addresses another user or problem.
- `FICTION_NEWS_OR_ENTERTAINMENT`: narrative/news/entertainment noise for this question.
- `INSUFFICIENT_CONTENT`: content is too thin or unavailable to judge.
- `EVALUATOR_UNAVAILABLE`: no semantic judgment was obtained.

## Derived QualificationSummary

Calculated from persisted rows; it is not a second canonical table.

| Field | Meaning |
|---|---|
| `status` | `REQUIRED`, `READY`, `INSUFFICIENT_RELEVANT_EVIDENCE`, or `UNAVAILABLE` |
| `total_evidence` | Current mission-evidence associations |
| `qualified_support` | `QUALIFIED_SUPPORT` count |
| `context_only` | `CONTEXT_ONLY` count |
| `excluded_irrelevant` | `EXCLUDED_IRRELEVANT` count |
| `unassessed` | Missing rows plus explicit `UNASSESSED` rows |
| `question_relevance_score` | Qualified-support observations divided by assessed evidence, as a percentage |
| `pending_batches` | Number of bounded reads still required |

`question_relevance_score` is reported separately. It does not erase coverage, localization,
freshness, or creator-diversity dimensions.

## Derived EvidenceSufficiency

Calculated per topic by deterministic policy.

| State | Contract |
|---|---|
| `SUFFICIENT_POSITIVE_SUPPLY` | At least one qualified demand observation and two qualified supply observations from two source ids |
| `SUFFICIENT_ZERO_SUPPLY` | At least one qualified demand observation and two relevant healthy-empty supply surfaces |
| `MISSING_DEMAND` | No qualified demand observation |
| `MISSING_SUPPLY` | Demand exists, but positive or measured-zero supply minimum is not met |
| `QUALIFICATION_REQUIRED` | At least one current observation is missing or unassessed |
| `QUALIFIER_UNAVAILABLE` | Semantic judgment failed or could not be obtained |

Only the two `SUFFICIENT_*` states permit an Opportunity Index.

## Derived QualifiedHandoffCandidate

An Attention cluster is eligible when:

- it is directly relevant to the Attention frame;
- at least two qualified observations belong to it; and
- those observations reference at least two canonical source ids.

Adjacent/context-only clusters remain visible in Attention results but are not handoff candidates.

## State transitions

### Workspace run

```text
writer claimed
    -> vocabulary synchronized
    -> connector probes executed
    -> observations/evidence written
    -> probe outcomes written
    -> mission COMPLETED
    -> qualification REQUIRED
    -> qualification batches submitted
    -> qualification READY
    -> sufficiency calculated
    -> verdict available OR insufficient evidence
```

If vocabulary synchronization fails, the mission fails before connector execution. If probe-outcome
storage fails, the mission does not become completed. If qualification fails, the completed raw
mission remains readable but Market verdicts remain blocked.

### Evidence replacement on a later run

- Pruned mission-evidence rows cascade their old qualifications.
- Retained observation qualifications remain valid because the mission frame and observation are
  unchanged.
- New mission-evidence rows begin unassessed and return the mission to `REQUIRED`.
- Probe outcomes from the new run supersede older outcomes only after the new run completes.

### Market revision

A new Market Brief revision already creates a new mission. It therefore starts with no evidence
qualifications. Earlier mission qualifications remain immutable and never satisfy the new mission.

## Deletion and security

- Deleting a mission cascades its run journals, which cascade probe outcomes, and directly cascades
  evidence qualifications.
- Deleting a run cascades only its probe outcomes.
- Deleting/pruning mission evidence cascades the corresponding qualification.
- PostgreSQL enables RLS on both new tables and grants no client role access.
- SQLite keeps foreign keys enabled and enforces the same uniqueness and value checks.
